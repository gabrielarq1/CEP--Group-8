Overview

Our project does not collect survey data. Every analytics objective (AO) works from published research, and the data the whole project rests on is the replication packet that Eisend, Niewiadomska, and van Noort posted on Harvard Dataverse for their Journal of Marketing meta-analysis of personalization (doi: 10.7910/DVN/KJRWWM). So this assignment applies the survey data-preparation workflow from Case 31 to the two SPSS files in that packet:

  • personalization.sav is our main project data. Each row is one effect size coded from a primary study, with the codes from coders 1, 2, and 3. It is the human benchmark for AO1 to AO3 and the base the AO4 evidence update adds to.
  • manager-survey.sav is a real survey. The authors asked 201 marketing managers how they use personalization and how useful and surprising they found six key findings. It is the closest thing in our project to survey data, and it speaks directly to PO2, the consultant playbook for TBFI.

Each learning objective maps onto these files as follows.

Step 1: Prepare the Raw Data Before Download

The Qualtrics steps in the assignment (deleting pretest responses and keeping only legitimate responses) have a direct equivalent for both files.

personalization.sav. We downloaded the full replication packet from Dataverse and checked it against the authors’ readme. The packet has four data files (personalization.sav, personalizationcorrelation.sav, manager-survey.sav, corrmatrix.xls), two R scripts, and four AMOS files. The authors’ exclude variable plays the role of “keep only legitimate responses.” Only rows with exclude = 0 enter their analyses, and their R scripts filter on it every time.

manager-survey.sav. The survey was fielded on Prolific in two rounds (July 8 and July 10). The file already flags testers and exclusions: tester, exclude, and a remarks field explaining why. The file also holds personal and device data (Prolific ID, city, latitude, longitude, browser, device model). None of that is needed for analysis, so it is dropped as the first cleaning step and never printed.

Create New Variables with mutate()

Three new variables, each with a job in the project:

  • var_check recomputes the sampling variance of r from its formula, (1 − r²)² / (n − 1). If it matches the authors’ VAR_RAW, we know how their variances were built, which AO1 needs when AI-extracted r and n replace the human values.
  • n_data_types counts how many of the five data types (demographic, psychographic, socioeconomic, geographic, behavioral) a personalization used. This is a dashboard-ready summary for AO4.
  • dv_agree flags whether coders 1 and 2 gave the same outcome category, which feeds AO2.
Code 
meta_inc <- meta_inc |>
  mutate(
    var_check = (1 - ES_RAW^2)^2 / (SAMPLE - 1),
    n_data_types = DEMOGRAPHIC_LEV2 + PSYCHOGRAPHIC_LEV2 + SOCIOECONOMIC_LEV2 +
                   GEOGRAPHIC_LEV2 + BEHAVIORAL_LEV2,
    dv_agree = if_else(as.numeric(DVcoder1) == as.numeric(DVcoder2), "agree", "disagree")
  )

meta_inc |>
  filter(!is.na(var_check), !is.na(VAR_RAW)) |>
  summarise(rows_checked = n(),
            max_abs_difference = max(abs(var_check - VAR_RAW)),
            correlation = cor(var_check, VAR_RAW)) |>
  kable(digits = 4, caption = "Recomputed Variance vs. the Authors' VAR_RAW")

Recode into Different Variables

The authors group the 44 outcome codes into broad families in their R script (personalization-integration.R): persuasion success (for example attitudes, intentions, trust) and persuasion failure (negative affect, avoidance, negative cognitions, intrusiveness, privacy concerns, suspicion). We recode DV into a new variable, dv_family, using exactly the code lists in their script, and keep the original DV untouched.

Code 
success_codes <- c(1, 3, 4, 5, 7, 30, 31, 8, 13, 16, 26, 35, 39, 41, 42)
failure_codes <- c(9, 12, 14, 24, 29, 38)

meta_inc <- meta_inc |>
  mutate(dv_family = case_when(
    as.numeric(DV) %in% success_codes ~ "Persuasion success",
    as.numeric(DV) %in% failure_codes ~ "Persuasion failure",
    TRUE ~ "Other outcome"
  ),
  dv_family = factor(dv_family, levels = c("Persuasion success", "Persuasion failure", "Other outcome")))

meta_inc |>

Reliability Analysis: Agreement Between Coders

In a survey, reliability asks whether the items of a scale hang together (Cronbach’s alpha). In a meta-analysis, the “instrument” is the codebook, and reliability asks whether two coders applying it independently reach the same code. The standard statistic for two coders and nominal codes is Cohen’s kappa. This is also the exact comparison AO2 runs for the AI coders.

Code 
kappa_row <- function(data, a, b, name) {
  x <- data |> select(all_of(c(a, b))) |> mutate(across(everything(), as.numeric)) |> drop_na()
  k <- cohen.kappa(as.matrix(x))
  tibble(code = name, rows_both_coded = nrow(x),
         percent_agree = round(100 * mean(x[[1]] == x[[2]]), 1),
         cohens_kappa = round(k$kappa, 3))
}

bind_rows(
  kappa_row(meta_inc, "DVcoder1", "DVcoder2", "Outcome category (44 codes)"),
  kappa_row(meta_inc, "demographic1", "demographic2", "Demographic data used"),
  kappa_row(meta_inc, "psychographic1", "psychographic2", "Psychographic data used"),
  kappa_row(meta_inc, "socioeconomic1", "socioeconomic2", "Socioeconomic data used"),
  kappa_row(meta_inc, "geographic1", "geographic2", "Geographic data used"),
  kappa_row(meta_inc, "behavioral1", "behavioral2", "Behavioral data used")
) |> kable(caption = "Inter-Coder Reliability, Coder 1 vs. Coder 2 (Included Rows)")

The outcome-category kappa is .857, the same value the authors report in the article, so our prepared data reproduce their reliability check. Values above .80 are usually read as strong agreement and .61 to .80 as substantial (Landis and Koch 1977), so every code here clears the usual bar. The roughly 13% of rows where the coders disagreed are where AO2 will focus.

The surprise ratings hang together well (α = .81). The usefulness ratings fall just under the usual .70 cutoff (α = .67). Dropping KF6 (“delivery mode does not matter”), the finding managers rated least useful, brings alpha to .70, right at the cutoff. The lower alpha makes sense: these items rate six different findings rather than measuring one construct, and almost everyone rated every finding as useful, which leaves little variance for the items to share. We keep all six items in the usefulness composite, because each one is a finding the playbook will cover, but we treat that index with caution and report the five-item version as a check.

## Create New Variables with `mutate()` {#sec-meta-mutate}

Three new variables, each with a job in the project:

- `var_check` recomputes the sampling variance of *r* from its formula, (1 − *r*²)² / (*n* − 1). If it matches the authors' `VAR_RAW`, we know how their variances were built, which AO1 needs when AI-extracted *r* and *n* replace the human values.
- `n_data_types` counts how many of the five data types (demographic, psychographic, socioeconomic, geographic, behavioral) a personalization used. This is a dashboard-ready summary for AO4.
- `dv_agree` flags whether coders 1 and 2 gave the same outcome category, which feeds AO2.

```{r}
#| label: meta-mutate
meta_inc <- meta_inc |>
  mutate(
    var_check = (1 - ES_RAW^2)^2 / (SAMPLE - 1),
    n_data_types = DEMOGRAPHIC_LEV2 + PSYCHOGRAPHIC_LEV2 + SOCIOECONOMIC_LEV2 +
                   GEOGRAPHIC_LEV2 + BEHAVIORAL_LEV2,
    dv_agree = if_else(as.numeric(DVcoder1) == as.numeric(DVcoder2), "agree", "disagree")
  )

meta_inc |>
  filter(!is.na(var_check), !is.na(VAR_RAW)) |>

            max_abs_difference = max(abs(var_check - VAR_RAW)),
```

## Reliability Analysis: Agreement Between Coders {#sec-meta-reliability}

In a survey, reliability asks whether the items of a scale hang together (Cronbach's alpha). In a meta-analysis, the "instrument" is the codebook, and reliability asks whether two coders applying it independently reach the same code. The standard statistic for two coders and nominal codes is Cohen's kappa. This is also the exact comparison AO2 runs for the AI coders.

```{r}
#| label: meta-reliability
kappa_row <- function(data, a, b, name) {
  x <- data |> select(all_of(c(a, b))) |> mutate(across(everything(), as.numeric)) |> drop_na()
  k <- cohen.kappa(as.matrix(x))
  tibble(code = name, rows_both_coded = nrow(x),
         percent_agree = round(100 * mean(x[[1]] == x[[2]]), 1),
         cohens_kappa = round(k$kappa, 3))
}

bind_rows(
  kappa_row(meta_inc, "DVcoder1", "DVcoder2", "Outcome category (44 codes)"),
  kappa_row(meta_inc, "demographic1", "demographic2", "Demographic data used"),
  kappa_row(meta_inc, "psychographic1", "psychographic2", "Psychographic data used"),
  kappa_row(meta_inc, "socioeconomic1", "socioeconomic2", "Socioeconomic data used"),
  kappa_row(meta_inc, "geographic1", "geographic2", "Geographic data used"),
  kappa_row(meta_inc, "behavioral1", "behavioral2", "Behavioral data used")
) |> kable(caption = "Inter-Coder Reliability, Coder 1 vs. Coder 2 (Included Rows)")
```

The outcome-category kappa is .857, the same value the authors report in the article, so our prepared data reproduce their reliability check. Values above .80 are usually read as strong agreement and .61 to .80 as substantial (Landis and Koch 1977), so every code here clears the usual bar. The roughly 13% of rows where the coders disagreed are where AO2 will focus.


## Recode Out-of-Range Values into New Variables {#sec-survey-recode}

The usefulness and surprise items are 7-point scales (1 = not at all, 7 = very much), but some responses are coded 0, which is not a valid scale point. The authors' own filter variable treats 0 as missing. We recode each item into a new variable (`_c` for clean) with 0 set to `NA`, and keep the originals.

```{r}
#| label: survey-recode
items <- c(paste0("KF", 1:6, "_useful"), paste0("KF", 1:6, "_surprise"))

survey |>
  summarise(across(all_of(items), ~ sum(as.numeric(.x) == 0, na.rm = TRUE))) |>
  pivot_longer(everything(), names_to = "item", values_to = "zero_responses") |>
  filter(zero_responses > 0) |>
  kable(caption = "Items with Out-of-Range Zero Codes")

survey <- survey |>
  mutate(across(all_of(items), ~ na_if(as.numeric(.x), 0), .names = "{.col}_c"))
```

## Reliability Analysis {#sec-survey-alpha}

```{r}
#| label: survey-alpha
useful_items <- survey |> select(ends_with("_useful_c"))
surprise_items <- survey |> select(ends_with("_surprise_c"))

a_useful <- psych::alpha(useful_items)
a_surprise <- psych::alpha(surprise_items)

tibble(scale = c("Usefulness of the six findings", "Surprise of the six findings"),
       items = c(6, 6),
       cronbach_alpha = round(c(a_useful$total$raw_alpha, a_surprise$total$raw_alpha), 3),
       mean_inter_item_r = round(c(a_useful$total$average_r, a_surprise$total$average_r), 3)) |>
  kable(caption = "Cronbach's Alpha for the Two Rating Sets")

tibble(item_dropped = names(useful_items),
       alpha_if_dropped = round(a_useful$alpha.drop$raw_alpha, 3)) |>
  kable(caption = "Usefulness: Alpha if Each Item Is Dropped")
```

The surprise ratings hang together well (α = .81). The usefulness ratings fall just under the usual .70 cutoff (α = .67). Dropping KF6 ("delivery mode does not matter"), the finding managers rated least useful, brings alpha to .70, right at the cutoff. The lower alpha makes sense: these items rate six different findings rather than measuring one construct, and almost everyone rated every finding as useful, which leaves little variance for the items to share. We keep all six items in the usefulness composite, because each one is a finding the playbook will cover, but we treat that index with caution and report the five-item version as a check.

## Create the Composite Scales {#sec-survey-composite}

```{r}
#| label: survey-composite
survey <- survey |>
  mutate(usefulness_index = rowMeans(across(ends_with("_useful_c")), na.rm = TRUE),
         usefulness5_index = rowMeans(across(KF1_useful_c:KF5_useful_c), na.rm = TRUE),
         surprise_index = rowMeans(across(ends_with("_surprise_c")), na.rm = TRUE))

survey |>
  summarise(across(c(usefulness_index, usefulness5_index, surprise_index),
                   list(mean = ~ mean(.x), sd = ~ sd(.x), min = ~ min(.x), max = ~ max(.x)))) |>
  pivot_longer(everything(), names_to = c("index", ".value"), names_pattern = "(.*_index)_(.*)") |>
  mutate(across(where(is.numeric), ~ round(.x, 2))) |>
  kable(caption = "Composite Scales (1 to 7)")

survey |>
  summarise(across(ends_with("_useful_c"), ~ mean(.x, na.rm = TRUE))) |>
  pivot_longer(everything(), names_to = "item", values_to = "mean_usefulness") |>
  mutate(finding = kf_names[substr(item, 1, 3)], mean_usefulness = round(mean_usefulness, 2)) |>
  select(finding, mean_usefulness) |>
  arrange(desc(mean_usefulness)) |>
  kable(caption = "Which Findings Managers Found Most Useful")
```

Managers rate the findings as clearly useful (about 6 out of 7) and only moderately surprising (about 4.5). For the TBFI playbook, that is a useful signal: the guidance is wanted, but much of it confirms what practitioners already suspect, so the playbook should lead with the findings that are both useful and less expected.
